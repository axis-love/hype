## Modes

When `prompts/system_global.md` is non-empty, Natalie operates in **raw-prompt mode**: all six `system_*` / `user_*` layers come from the markdown files, and `profile.json`'s `compile()` is bypassed for prompts. `profile.json` still provides the few-shot examples (`example_posts` / `example_replies`).

When `system_global.md` is empty/missing, Natalie compiles prompts from `profile.json` automatically.

The current setup is **raw-prompt mode** — tuned for ~27B-class models with explicit anti-hallucination rules.

## PKB Note

`projects.json` is **seed data only**. On first run, `core/project_kb.py` migrates its contents into the `projects` SQLite table. This migration is idempotent — subsequent runs skip IDs that already exist in the DB.

**Editing `projects.json` after the first migration has NO effect.** The SQLite `projects` table is the source of truth. Use Jessica's `/app` commands to manage projects:

- `/app list` — show all projects
- `/app show <id>` — display a project's full KB
- `/app new <id>` — create a project
- `/app set <id> <field> <value>` — update a field
- `/app fact <id> <YYYY-MM-DD> <text>` — add a recent fact
- `/app dont add <id> <claim text>` — add a do-not-claim entry
- `/app feature add <id> <name>` — add a feature

Lane-aware retrieval injects exactly one project's KB block into project-lane generations (not the whole catalog). Per-project facts were stripped from `system_global.md` and live only in the PKB.

## Grounding sources (current)

- **`projects.json`** — PKB **seed only**. On first worker run it migrates into the SQLite `projects` table, which is then the source of truth (edits to this file after that have no effect). Lane-aware retrieval injects exactly one project's KB block into `project`/`devlog`-lane generations (not the whole catalog); other channel lanes get a condensed `do_not_claim` guardrail. Detailed per-project facts (features, do-not-claim, recent facts) are **not** baked into `system_global.md` — they are injected per generation from the PKB. Manage projects with the `/app …` commands. See [Project Knowledge Base](../../Documentation/Modules/Project-Knowledge-Base.md).
- **`lore.json`** — Git-managed data file of stable personal canon. The active canon Natalie uses is currently expressed directly in `system_global.md`; a dynamic per-generation lore loader is **not** wired (see [Documentation/Roadmap.md](../../Documentation/Roadmap.md)).

For the full persona model (repo-managed vs DB precedence, raw-prompt vs compiled mode), see [Persona Configuration](../../Documentation/Modules/Persona-Configuration.md).
